# 《第六国兴衰录》设定资料库

> 一部以「档案库」形态呈现的架空历史小说之工作底本。
> 体例：**编年史 + 个人史** 双线；卷首以《再版说明》为前言（拟新民社出版局口吻）。

本仓库只做一件事：**把散落在讨论稿里的设定，整理成无矛盾、可直接下笔的文档。**

## 二、怎么读这套文档

1. **先读 [docs/00-使用说明与正典规则.md](docs/00-使用说明与正典规则.md)** —— 五条铁律与标记约定，不读会误用其它文档。
2. 要写某一场戏，按需查：
   - 时间、年代、换算 → [03-纪年与历法](docs/03-纪年与历法.md)
   - 谁掌什么权、怎么任命 → [04-政体与权力结构](docs/04-政体与权力结构.md)
   - 地图、行政区、首都在哪 → [01-世界与地理](docs/01-世界与地理.md)
   - 谁说了一句什么话、官方口吻怎么写 → [13-话语样本与文体](docs/13-话语样本与文体.md)
   - 某人履历、结局 → [10-人物志](docs/10-人物志.md)
   - 这个名词到底该写哪个字 → [11-专名表](docs/11-专名表.md)
3. 写作中出现新设定，**先补 `docs/`，再写正文**。正文不得成为唯一设定来源。

## 四、体例约定（摘要，详见 docs/00）

- 设定分三级：**[定]** 可写、**[待定]** 写时须回避或标注、**[建议]** 我的推断，未经作者确认不入正文。
- 一切专名以 [11-专名表](docs/11-专名表.md) 为准；表中「误写」一栏的名字，任何文档不得再使用。
- 纪年一律「事件名（纪年）」，例：`玷污惨案（光荣纪元前五年）`；正文中出现的纪年口径，由 [03-纪年与历法](docs/03-纪年与历法.md) 统一。

## 五、路线图

1. **当前**：设定整理（本仓库第一版）。
2. 作者裁定 `99-待决议题` 中的专名与情节冲突 → 逐条写入 `decisions/`，回改 `docs/`。
3. 补写 `docs/文献库/`：《升力》章目、《升命力》批注本、新民社社论选、绩效法典条文、通志各卷——这些既是设定，也是将来正文里"翻到的文件"。
4. 正文工程：先写「卷首 + 编年史第一卷」，再写「个人史第一卷」，两条线交替推进；文献挟带件按需插入。

## 六、git

```bash
git log --oneline          # 每次改动一句话说明改了什么
git diff                   # 改设定前先看差异
```

**提交前先自检**：

```bash
pwsh -File tools/check.ps1
```

它会检查：禁用写法是否回流、`〔D-xx〕` 与 `A-xx` 引用是否落地、内部链接是否死链、编号是否重复、
几处硬约定数字是否还在。全绿再提交。

**换行符统一 LF**。`.gitattributes` 已设 `text=auto eol=lf`，本仓库另设 `core.autocrlf=false`、`core.eol=lf`；
`tools/check.ps1` 会把任何 CRLF 文件报出来。Windows 编辑器请设成 LF，别让它改回去。

一次提交只做一件事：改专名、补设定、改正文，分开提交。
